# ADR-002: AI Inference Strategy

## Context
Local AI copilot for note structuring, formatting, linking, tagging. Must work on CPU-only (no GPU), streaming tokens, cancelable, and respect user approval.

## Decision
**Sidecar process using llama.cpp GGUF models:**
- Run `llama-server` or Rust bindings as a separate process.
- Models: quantized GGUF (Qwen3/Llama/Gemma family, permissive license).
- Embeddings: small multilingual model (bge-m3 / multilingual-e5 / nomic-embed).
- Hardware detection at runtime: Metal (macOS), Vulkan/CUDA (Windows/Linux), AVX2/NEON (CPU fallback).

## Alternatives
| Option | Pros | Cons |
|---|---|---|
| llama.cpp sidecar vs ONNX Runtime | No network, fast streaming, local only | Requires Rust bindings or shell wrapper |
| OpenAI API vs local models | Better quality out-of-the-box | Violates privacy/offline requirement |

## Rationale
Zero network calls. Local inference on CPU/GPU. Streaming tokens with cancellation. Quantized GGUF keeps model size manageable (~2-4 GB for base models).

## Limitations
- First suggestion latency < 3s from embedding index (measured profile TBD)
- Structured generation time acceptable on notebook 8GB RAM without GPU
