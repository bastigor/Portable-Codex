# ADR-004: Data Model & File Format

## Context
Every note is a readable `.md` file with YAML frontmatter. No proprietary formats. Index is derived SQLite DB, always reconstructible from files.

## Decision
**File format:**
- Primary: Markdown (.md) — CommonMark + GFM (GitHub Flavored Markdown)
- Frontmatter: YAML at top of each .md file (`---` delimiters)
- Block IDs: `[[nota]]`, `[[nota#sec]]`, `[[nota^bloco]]`
- Tags, properties via frontmatter fields
- Backlinks: wikilinks + separate backlink table in SQLite

## Alternatives
| Option | Pros | Cons |
|---|---|---|
| Proprietary vault format vs Markdown | Obsidian native | Violates Principle 1 (no proprietary source of truth) |

## Data Model (SQLite)
- **Notes**: id, title, body, frontmatter (jsonb), links (table), tags (jsonb), properties
- **Links**: note_id, target_note_id, type (wikilink, backlink, mention)
- **Tags**: tag_name, note_id (many-to-many)
- **Properties**: property_key, property_value, note_id
- **Embeddings**: vector column for each note (sqlite-vec)

## Round-trip guarantee
Open and save without edits must produce byte-identical file. Tests with real Obsidian vault corpus.
