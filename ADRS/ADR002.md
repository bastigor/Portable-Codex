## Context

We need to integrate local AI for:
- Semantic search (embeddings)
- Link suggestions
- Note structuring
- Formatting assistance

Options:
1. **llama.cpp Python bindings** (simplest but less control)
2. **llama.cpp Rust bindings** (best integration, most control)
3. **llama-server sidecar + HTTP/JSON-RPC** (isolated, cancellable, streamable)

## Decision: **llama-server Sidecar with JSON-RPC IPC**

### Architecture

Frontend (Tauri) <HTTP/JSON-RPC> llama-server (llama.cpp)
  |                    ^
  |           Unix socket / named pipe
  v
Backend Rust (IPC + SQLite)

### Benefits

1. **Cancellation support**: Cancel generation at any point
2. **Streaming tokens**: Real-time feedback without buffering
3. **Memory isolation**: AI crashes don't crash the app
4. **Priority queue**: Interactive typing > background indexing
5. **Hardware detection**: Separate process can detect GPU/Metal/Vulkan

### Model Strategy

| Use Case | Model | Size | Quantization |
|----------|-------|------|--------------|
| Embeddings | bge-m3-small en-v1.5 or all-MiniLM-L6-v2 | ~140-200 MB | Q4_K_M |
| LLM (structuring) | Qwen3 0.5B/1.8B or Phi-3-mini | ~1-2 GB | Q4_K_M |
| LLM (linking) | Same as above | ~1-2 GB | Q4_K_M |
