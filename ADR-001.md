# ADR-001: Tauri v2 como Framework Desktop

**Data:** 2026-11-24  
**Status:** Em revisão após spikes  

## Contexto
Precisamos de framework desktop que:
1. Tenha binário pequeno (<50MB) para pendrives
2. Funcione em Windows, macOS, Linux sem dependências complexas
3. Permita editor web leve (React/TypeScript)
4. Mantenha portabilidade total (dados apenas em /data)

## Alternativas Analisadas

| Critério | Tauri v2 | Electron | 
|----------|----------|----------|
| Tamanho binário | 25-50 MB | 180-250 MB |
| Dependências externas | WebView2 (risco ~15% Windows) | Zero |
| Inicialização fria | 3-6s (depende de OS) | 2-4s |
| Memória em uso | 100-200 MB | 400-800 MB |
| Webview sandboxing | Excelente | Bom |
| Portabilidade Linux | AppImage estático | NPM + Node complexos |
| Aprendizado curva | Média (Rust) | Baixa (JS/TS) |

## Decisão: Tauri v2 com WebView2 Embutido

**O que fazemos:**
1. Usar Tauri v2 como framework principal
2. Embarcar WebView2 fixed-version no build Windows via `@tauri-apps/plugin-shell` + script de patch do runtime
3. Executar testes de fallback: se WebView2 falhar, exibir erro claro com link para Microsoft Store/Edge download
4. Para macOS: usar WebKit nativo (já vem)
5. Para Linux: AppImage com GTK3+WebViewGTK (testar compatibilidade)

**Por que essa decisão:**
- **Portabilidade:** Binário 70% menor que Electron → pendrive de 32GB cabe tudo com margem
- **Performance:** Memória 50% menor, melhor sandboxing do webview
- **Futuro-proof:** Tauri é ativo, pequeno, Rust-backed
- **Trade-off aceitável:** ~15% de Windows não terão WebView2 → instruções claras no instalador

## Risk Acceptance
- **WebView2 não instalado:** Documentar solução (Edge download + enable flags), ou oferecer instalação em segundo passo do script
- **Linux WebviewGTK inconsistente:** Fallback para AppImage com dependências mínimas explicitadas
- **Cold start 5s Windows:** Aceitável (<5s meta); otimização futura via WebView2 cache
